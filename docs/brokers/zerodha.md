# Zerodha Kite Connect v3 — zerodha
Docs: https://kite.trade/docs/connect/v3/ (user, orders, portfolio, exceptions, market-quotes); forum https://kite.trade/forum/discussion/comment/52157 ; https://kite.trade/forum/discussion/16276/market-protection-is-it-enforced-today-and-what-happens-to-any-unfilled-quantity

- **1. Auth flow + token lifetime**: OAuth-style redirect. Open Kite login with `api_key` -> user logs in -> redirect to the URL registered in the developer console with `request_token` query param -> `POST /session/token` with `api_key`, `request_token`, `checksum` = SHA-256(api_key + request_token + api_secret) -> `access_token`. request_token lives only a few minutes. access_token expires 6 AM next day (regulatory), so daily re-login is needed; `DELETE /session/token` logs out. User supplies api_key, api_secret, login. Redirect URL is fixed in the console. Auth header format UNVERIFIED on this page. Src: https://kite.trade/docs/connect/v3/user/
- **2. Holdings**: `GET /portfolio/holdings`. Fields `tradingsymbol`, `quantity` (settled, T+2 delivered), `t1_quantity` (T+1 pending), `average_price`, `collateral_quantity` (pledged), `isin`, `authorised_quantity`, `used_quantity`. Sell needs depository authorisation (demat PIN/TPIN). Src: https://kite.trade/docs/connect/v3/portfolio/
- **3. Funds**: `GET /user/margins/:segment` (equity / commodity). Exact available-cash field path (`available.cash`) UNVERIFIED (page excerpt only said "cash"). Src: https://kite.trade/docs/connect/v3/user/
- **4. Place order**: `POST /orders/:variety` (variety value list e.g. regular/amo/co/iceberg/auction: UNVERIFIED in fetch). Required: `tradingsymbol`, `exchange` (NSE/BSE/NFO/CDS/BCD/MCX), `transaction_type` BUY|SELL, `order_type` MARKET|LIMIT|SL|SL-M, `quantity`, `product` (CNC = delivery; also NRML, MIS, MTF), `validity` (DAY|IOC|TTL). Src: https://kite.trade/docs/connect/v3/orders/
- **5. Tag**: `tag`, max 20 alphanumeric chars. Src: https://kite.trade/docs/connect/v3/orders/
- **6. Order state**: `GET /orders` (all of the day's orders = order book), `GET /orders/:order_id` (history of one order). Statuses: OPEN, COMPLETE, CANCELLED, REJECTED, plus interim "VALIDATION PENDING", "OPEN PENDING" (full list UNVERIFIED). Mapping: COMPLETE->FILLED; OPEN with `filled_quantity`>0 and `pending_quantity`>0 -> PARTIAL (no PARTIAL status exists); interim -> OPEN. Src: orders page + forum 16276 above.
- **7. Instruments**: `instrument_token` + `exchange_token`, keyed by `tradingsymbol` + `exchange`. Master: `GET /instruments` or `/instruments/:exchange`, gzipped CSV (instrument_token, exchange_token, tradingsymbol, name, last_price, expiry, strike, tick_size, lot_size, instrument_type, segment, exchange), regenerated daily (fetch ~08:30). Base host https://api.kite.trade UNVERIFIED in fetch. Src: https://kite.trade/docs/connect/v3/market-quotes/
- **8. Rate limits**: per s: orders 10/s, other endpoints 10/s, quote 1/s, historical 3/s; per min: 400 orders; per day: 5000 orders/user/API key; 25 modifications per order. Src: https://kite.trade/docs/connect/v3/exceptions/
- **9. Regulatory**: Static IP whitelist required for ORDER endpoints only (register at developers.kite.trade profile > "IP Whitelist"); unregistered IP -> orders rejected; non-order endpoints work from any IP. Limit 10 orders/s per client ID (across all apps); more needs exchange-registered strategy. IP may be shared among family only. Effective date CONFLICT: forum fetch said 1 Apr 2024, search snippets said 1 Apr 2026 — treat as UNVERIFIED, enforce IP now. Src: https://kite.trade/forum/discussion/comment/52157 ; support page https://support.zerodha.com/category/trading-and-markets/general-kite/kite-api/articles/static-ip
- **10. MARKET/MPP**: `market_protection` param mandatory on MARKET and SL-M via API (place and modify); 0 is rejected; `-1` = automatic; custom value >0 to 100 (%). Without it error: "Market orders without market protection are not allowed via API. Please set market protection or use a Limit order." Partially filled residual stays OPEN (same order_id), not cancelled. Src: forum 16276, comment/52157, orders docs.
- **11. Cost**: Personal API free (orders, GTT, portfolio, margins; NO market data); Connect Rs 500/month per app adds websockets + historical; startup program free. Src: https://support.zerodha.com/category/trading-and-markets/general-kite/kite-api/articles/what-are-the-charges-for-kite-apis
- **12. Errors**: JSON `{"status":"error","message":"...","error_type":"<Exception>"}`. 403 + TokenException = session expired -> re-login. 429 = rate limit (Retry-After header UNVERIFIED). Rejects: OrderException / InputException (400). Insufficient funds: MarginException; insufficient holdings: HoldingException. 502/503/504 = OMS/gateway trouble (ambiguous for placement). Src: https://kite.trade/docs/connect/v3/exceptions/
- **13. Sandbox**: UNVERIFIED (none found in official docs).

## Defensive defaults (remaining BLOCKING items, DECISIONS D19)
- **Auth header, base host, `variety` list**: F1 step 2. Copy these constants from the official `kiteconnect` SDK source into our httpx adapter. Never wrap the SDK's `place_order` or any other order call (D25). Until a real call succeeds, send only `variety=regular`.
- **Full status list**: COMPLETE -> FILLED, REJECTED -> REJECTED, CANCELLED -> CANCELLED, OPEN and interim states (VALIDATION PENDING, OPEN PENDING, ...) -> OPEN. PARTIAL when `filled_quantity` > 0 on a non-terminal status. Any other string becomes non-terminal and, at timeout, UNKNOWN. Never FILLED, never resubmitted.
- **F1 step 3**: ship with `experimental=true`, contract tests and a README disclosure unless live-tested.

## Gotchas
- No native PARTIAL status; derive from filled/pending quantity.
- 5xx/504 on place_order is ambiguous: reconcile via `GET /orders` + tag, never resubmit.
- Daily 6 AM token expiry forces a human-in-loop login each day.
- Forum threads report "Failed to apply market protection" errors on MPP orders (https://kite.trade/forum/discussion/comment/51750/).
- Holdings `quantity` excludes `t1_quantity` and collateral; sellable qty = quantity (+ t1 caveats) minus used/collateral.
